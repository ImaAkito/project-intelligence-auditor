# Product Audit

The product audit asks whether the existing technology forms a coherent product for a specific user and workflow.

Assess:

- target user clarity;
- problem severity;
- core workflow completeness;
- time to first value;
- usability of the critical path;
- configuration/setup burden;
- failure recovery;
- explainability of outputs;
- onboarding readiness;
- documentation for users;
- support requirements;
- missing product capabilities;
- unnecessary features;
- competing product directions.

## Product versus technology

Do not equate a functioning algorithm, API, model, or hardware prototype with a product.

Explicitly identify:

- Technology → Product gaps;
- incomplete end-to-end workflows;
- manual steps that prevent repeatable use;
- developer-only assumptions;
- missing permissions/auth where relevant;
- missing lifecycle operations;
- missing user feedback loops;
- product claims not demonstrated by current behavior.

## MVP

Define MVP around one or more complete user outcomes rather than feature count.

For each MVP requirement record:

- user value;
- current evidence;
- status;
- blockers;
- acceptance criteria.

## Scope discipline

Identify features or work that should be deferred because they:

- do not unlock the critical path;
- optimize an unvalidated workflow;
- duplicate another implementation;
- increase support burden without meaningful user value;
- polish UI while core behavior remains unvalidated.

## Next version

The recommended next version must state:

- included scope;
- excluded scope;
- acceptance criteria;
- quality gates;
- definition of ready.
